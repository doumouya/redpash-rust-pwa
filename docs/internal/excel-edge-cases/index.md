# Excel edge-case catalog

> **Internal — RedPash team only.** Not part of the public product docs.

The triage board for **Workstream 4 — Excel + JSON edge cases**. Where the
~100-file CSV stress corpus (`clean-score/raw/`) hammers the CSV path, a
matching set of deliberately dirty `.xlsx` fixtures hammers the **Excel**
path: `parse.rs` (sheet pick / header / preamble), `dtype.rs` (column
typing), `encoding.rs`, and `joins.rs` (key detection).

This catalog is the *in-flight* board — one row per edge-case class, with
the fixture that exhibits it and a status. When a class is actually
root-caused and fixed, it graduates to a [Runbook](../runbook/index.md)
entry (the settled post-mortem record). Catalog = open work; runbook =
closed work; they cross-link.

## Workflow

1. Run the corpus through the Excel-import path; for each EXL-NN, set the
   status (`open → seen → RCA → fixed`).
2. New failure class not yet listed? Add a row — keep IDs sequential.
3. When a class is fixed: write a [Runbook](../runbook/index.md) entry
   (`NNNN-slug.md`, the 5-section format), flip the row to `✅ fixed`, and
   link the entry.
4. Keep `score_dir.rs` green — it's the regression harness (Workstream 4d).

## Known before the campaign

The team note already flagged a `parse.rs` header-detection bug (CSV side,
Excel-relevant): Pass 1 only commits a header with **≥2 delimiters (≥3
columns)**; Pass 2 handles 1-column files — a **2-column non-comma file**
falls between them. Also: a preamble line carrying ≥2 delimiters can be
mistaken for the header (overlaps **EXL-06**). First fix to land → first
runbook entry of this campaign (`0002`).
