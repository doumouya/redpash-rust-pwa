# Database schema

Postgres-only. Migrations live in [`backend/migrations/`](../../backend/migrations/)
and are applied automatically at startup via
`sqlx::migrate!("../../migrations")` in `AppState::init` — so shipping
a schema change means adding a new `NNNNNN_*.sql` file and restarting
the api crate. `sqlx-cli` is only needed for hand-running migrations
against CI databases.

---

## RedPash-IDs

Every persisted row's primary key is a typed prefix + uuid simple-hex.
Generated by `id::new("PFX")`. See [redpash-id.md](redpash-id.md) for
the format spec; the prefix table below maps each prefix to its
table.

| Prefix | Entity                                | Allocator |
|--------|---------------------------------------|-----------|
| `USR`  | User (`users`)                        | `bootstrap.rs::run`, `db::upsert_google_user` |
| `SES`  | Session (`sessions`)                  | `db::create_session` |
| `PRJ`  | Project (`projects`)                  | `db::insert_project`, `db::ensure_default_project` |
| `FIL`  | Project file (`project_files`)        | `routes::files::upload`, `routes::files::create_join`, `routes::files::snapshot` |
| `STP`  | Project step (`project_steps`)        | `routes::files::add_step` |
| `RPT`  | Report (`reports`)                    | `routes::reports::create` |
| `DSH`  | Dashboard (`dashboards`)              | `routes::dashboards::create` |
| `CMP`  | Company (`companies`)                 | `db::create_company` |
| `EVT`  | Event — **reserved**, no table yet    | — |
| `CAS`  | Case — **reserved**, no table yet     | — |

The membership join tables (`company_memberships`, `project_memberships`)
carry no RedPash-ID — they use a composite PK `(parent, user)` and are
never addressed in a URL.

## Tables

### `users`

Identity anchor. Two creation paths:

- **Bootstrap** — `crates/api/src/bootstrap.rs` inserts a single user
  with `username = 'dev'` on first start. Acts as the dev_user fallback.
- **Google OAuth** — `db::upsert_google_user` matches on `google_sub`;
  INSERT on miss, refresh `email/display_name/avatar_url` on hit.

| `email`        | `TEXT`        | YES      | —            | From Google's `email` claim. |
| `display_name` | `TEXT`        | NO       | —            | Bootstrap = `"Dev user"`; OAuth = Google `name` claim or email local part. |

### `file_stages` (view)

Mig 009. Read-only view, one row per `project_files` row, classifying
the file by the furthest point it has reached in the
**import → clean → report → publish** pipeline:

| Column               | Type   | Notes |
|----------------------|--------|-------|
| `file_redpash_id`    | `TEXT` | → `project_files.redpash_id` |
| `project_redpash_id` | `TEXT` | → `projects.redpash_id` |
| `stage`              | `TEXT` | `import` / `clean` / `report` / `publish` |
| `stage_rank`         | `INT`  | `0`–`3` — numeric stage, so the project query can `MAX()` it |

Stage logic (highest match wins): `publish` — a report sourced from
the file is referenced by a widget in a **public** dashboard;
`report` — the file is `source_file_id` of ≥1 report; `clean` — the
file has ≥1 `project_steps` row; else `import`. `db.rs` joins this
view for the file list and aggregates `MAX(stage_rank)` for each
project's `stage` (with `import` as the empty-project default).

### `project_steps`

Append-only history powering apply / undo / redo. `applied` flips
`FALSE` on undo (history stays so redo can flip it back). A new step
INSERT clears the redo stack via
`DELETE … WHERE applied = FALSE`.

| Column            | Type          | Nullable | Default       | Notes |
|-------------------|---------------|----------|---------------|-------|
| `redpash_id`      | `TEXT` PK     | NO       | —             | `STP_…` |
| `file_redpash_id` | `TEXT` FK     | NO       | —             | → `project_files.redpash_id` `ON DELETE CASCADE` |
| `ordinal`         | `INTEGER`     | NO       | —             | Position in the file's step list. `MAX(ordinal)+1` on insert. |
| `kind`            | `TEXT`        | NO       | —             | See *Step kinds* below. |
| `params`          | `JSONB`       | NO       | `'{}'::jsonb` | Per-step params. |
| `applied`         | `BOOLEAN`     | NO       | `TRUE`        | `FALSE` = undone but still in the redo stack. |
| `created_at`      | `TIMESTAMPTZ` | NO       | `now()`       | |

**Step kinds** (actual values written by the cleaner — see
[`data/src/steps.rs`](../../backend/crates/data/src/steps.rs)):
`drop_columns`, `rename_column`, `drop_rows`, `drop_nulls`,
`fill_nulls`, `change_case`, `replace_text`, `fix_invalid`.

**Indexes:**

| Index                       | Columns                            | Notes |
|-----------------------------|------------------------------------|-------|
| `project_steps_pkey`        | `redpash_id`                       | PK |
| `project_steps_file_idx`    | `(file_redpash_id, ordinal)`       | List query (`ORDER BY ordinal ASC`) |

### `sessions`

Server-issued session cookies for Google OAuth users. The browser
never sees Google's tokens — the backend exchanges the auth code,
keeps the access token in memory just long enough to fetch userinfo,
and discards it. The `rp_session` cookie carries only this row's
`redpash_id`.

| Column            | Type          | Nullable | Default | Notes |
|-------------------|---------------|----------|---------|-------|
| `redpash_id`      | `TEXT` PK     | NO       | —       | `SES_…`. Value of the `rp_session` cookie. |
| `user_redpash_id` | `TEXT` FK     | NO       | —       | `ON DELETE CASCADE` → users |
| `expires_at`      | `TIMESTAMPTZ` | NO       | —       | 30 days from creation (`SESSION_TTL_DAYS`). |
| `created_at`      | `TIMESTAMPTZ` | NO       | `now()` | |

`find_session_user` auto-deletes expired rows on lookup so the table
self-trims under normal traffic.

**Indexes:**

| Index                     | Columns           | Notes |
|---------------------------|-------------------|-------|
| `sessions_pkey`           | `redpash_id`      | PK |
| `sessions_user_idx`       | `user_redpash_id` | List a user's sessions / cascade delete |
| `sessions_expiry_idx`     | `expires_at`      | Pruning candidate scans |

## Permissions model

Phases 4a + 4b + 4c have shipped:

- **4a** Google OAuth code flow → `users.google_sub` + `sessions`.
- **4b** Per-user data scoping — every owner-scoped list endpoint
  resolves the user via the `rp_session` cookie before querying.
- **4c** Per-resource ownership checks on every detail endpoint —
  `db::project_owner` / `report_owner` / `dashboard_owner` /
  `file_owner` look up the owner via the FK chain to `projects.owner_id`
  and `routes::ensure_owner` 404s on miss or mismatch (same
  `kind="not_found"` either way, so existence isn't leaked). Profile +
  Settings pages backed by `PATCH /api/me` (sparse field update +
  shallow merge of the `prefs` JSONB).

Still pending:

- Share-link UI for `reports.is_public` / `dashboards.is_public`. The
  columns exist; no toggle surface yet.

The sharing model stays "publish RID, anyone with the link reads" —
no folder ACLs. Folders are organisational labels only.
